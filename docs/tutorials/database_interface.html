Database Interface

This tutorial illustrates the Database interface class of powfacpy, which provides methods to export and import larger chunks of data from the PowerFactory database. Unlike exporting to formats such as CGMES, the Database class preserves a structure that stays close to the native PowerFactory database layout.

Typical use cases include:

  • Exporting larger chunks of data from PowerFactory objects — for example, to include in a project report or to share with others who can apply the settings in their own project
  • Conveniently exporting result variables such as simulation results or network element settings
  • Exporting and importing parameters of dynamic models (composite models and their controllers)

The tutorial is structured as follows. The first part covers exporting, importing, and comparing attributes of PowerFactory objects using Python dictionaries, JSON, and pickle format. The second part demonstrates how to export result variables to pandas DataFrames or CSV files. The final section focuses on exporting and importing controller parameters of dynamic composite models.

1 Introduction to the Database Interface

The Database class of powfacpy provides an interface to the PowerFactory database and simplifies the export and import of data.

1.1 Export to Dictionary

Suppose we want to extract selected parameters from terminals, loads, and transformers (or possibly any other object from the database). We define a dictionary with class names as keys and lists of parameter names as values.

from powfacpy.applications.database import Database

pfdb = Database(app)

class_params = {
    "ElmTerm": ["outserv"],
    "ElmLod": ["plini", "qlini", "typ_id.aP"],
    "ElmTr*": ["typ_id"],
}

Note that class names support wildcards (e.g. "ElmTr*"), and parameter names can reference attributes of a linked object using dot notation (e.g. "typ_id.aP").

Next, we retrieve the objects of interest and use get_object_attributes to extract a dictionary. The keys are PowerFactory objects and the values are dictionaries mapping attribute names to their values.

try:

1.2 Export from or Import to File

Using string paths instead of objects (as shown above) is required when saving data to a pickle file. This is useful for sharing data with colleagues who can load the dictionary and apply the settings in their own project (as demonstrated below).

import pickle

# save dict to pickle file
with open(r'.\output\model_data_export\database_dict.pickle', 'wb') as handle:
    pickle.dump(obj_attr, handle)

# load dict from pickle file
with open(r'.\output\model_data_export\database_dict.pickle', 'rb') as handle:
    obj_attr_loaded:dict  = pickle.load(handle)

To export parameters to a pickle file, reimport them later, and apply the settings back to PowerFactory, use the following workflow:

try:
    app.Hide()

    # save dict to pickle file
    with open(r'.\output\model_data_export\database_dict.pickle', 'wb') as handle:
        pickle.dump(comp_model_pars, handle)

    # load dict from pickle file
    with open(r'.\output\model_data_export\database_dict.pickle', 'rb') as handle:
        comp_model_pars_loaded  = pickle.load(handle)

    # modify the loaded dict to validate that the set_composite_model_parameters method works as expected

    # Set all parameters and reload
    pfdb.set_composite_model_parameters(comp_model_pars_loaded)    
    comp_model_pars = pfdb.get_composite_model_parameters(obj_format="path")
